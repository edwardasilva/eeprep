[eeprep](https://github.com/edwardasilva/eeprep) is open source. If you used the guide, hire electrical engineers or computer scientists, or work as one, you can correct what these pages get wrong.

## The best ways to help

The most useful help is a correction with a public source behind it. In order of how much each one helps:

1. Report a mistake. A wrong fact, a dead link, or advice that did not work for you. Name the page, and link a public source if you have one.
2. Say what happened in your own search. If a page helped you land an internship or job, or sent you the wrong way, open an idea and say which page and what happened. Real results shape the next release.
3. Send a source. A public page that backs up or contradicts a claim on the site. Every claim on the site needs one.
4. Fix a small thing yourself. A typo, a dead link, or one unclear sentence. The steps are below, and you only need a GitHub account.

## Suggest an idea or a fix

Open an [issue](https://github.com/edwardasilva/eeprep/issues/new/choose) and pick "Fix something" or "Idea or suggestion". A short description is all it needs. Naming the page and linking a public source help when you can. Maintainers check every claim against a real public source during review. When a fact on a page turns out to be wrong, the fix shows up in the [release notes](https://github.com/edwardasilva/eeprep/releases).

## Edit a page in your browser

You can fix a page without installing anything:

1. Find the page's file on [GitHub](https://github.com/edwardasilva/eeprep). Guide pages live in `src/content/docs`, and the file path follows the page address. The page at `eeprep.com/advice/resume/cleanup/` is the file `src/content/docs/advice/resume/cleanup.mdx`.
2. Click the pencil icon (Edit this file). GitHub makes your own copy of the repo the first time.
3. Make one change: one fix, or one page. A small change is quick to review and easy to undo.
4. If you add an outside link, paste it in the pull request too. Maintainers add the source entry for you.
5. Click "Commit changes", then "Propose changes", then "Create pull request". Write a sentence or two on what you changed and why. That is all a pull request needs.

## Work on your computer

For a bigger change, or to see the page before you send it, the [contribution guide](https://github.com/edwardasilva/eeprep/blob/main/.github/CONTRIBUTING.md) lists the commands to clone the repo, preview the site, and run the same checks the maintainers run. The checks are optional for you. Maintainers run them before a change goes in.

## What happens next

A maintainer reviews the pull request and may ask a question or suggest a change. Each accepted change goes in as one squashed commit. It shows on eeprep.com with the next release.

## Conduct

Be kind and assume good intent. To report a problem with someone's behavior, use GitHub's Report content feature or message the repository owner in private.

For a security problem, follow the [security policy](https://github.com/edwardasilva/eeprep/blob/main/.github/SECURITY.md). Do not open a public issue.
