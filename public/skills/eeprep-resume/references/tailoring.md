# Tailoring a resume to a posting

A resume works best when it is tailored to the posting in front of it. Doing that for every single application is often unrealistic, so the eeprep author recommends keeping 4 or 5 versions, each aimed at one niche or one level of effort, and picking the closest one for each application. Tailor the one that matters most by hand.

## Versions to keep

Pick the niches from the roles the user actually wants. For an EE student that is often a set like:

1. Embedded firmware and low-level software
2. Hardware design, PCB, and power
3. Test, validation, and manufacturing
4. Signals, controls, or RF, if the user has that work
5. A general version for career fairs and referrals, where the reader has not named a role

The same facts appear on every version. What changes is which projects lead, which bullets get the second line, which courses appear on the coursework line, and the order and wording of the Skills lines. Nothing is added to a version that is not true on every version.

## How to tailor one version to one posting

1. Read the posting and list its required and preferred items: tools, languages, protocols, standards, degree, years, location.
2. For each item, find where the user has already done it, in the inventory or on the current page. Mark each one as: shown, done but not shown, or not done.
3. For "done but not shown", surface it. Move the project up, give its bullet the second line, add the tool to the Skills line, or add the course to the coursework line. Use the posting's own word when the user's experience is the same thing: write CAD when the posting says CAD, write "3D drawings" when it says that.
4. For "not done", leave it off. Say to the user which requirements the page does not meet and whether they are tools and years (apply anyway) or a degree or license (usually a hard filter).
5. Reorder, do not rewrite. The bullets already hold the facts. Tailoring moves and trims. If you find yourself writing a new claim, stop and ask whether it is true.
6. Keep the one-line role statement, if there is one, in step with the posting's title.

## Acronyms and the two-layer screen

Most employers store applications in an applicant tracking system (ATS). Many of those systems do not auto-reject on resume content, though knockout questions on the form can. Some systems and some newer tools also score the page against the posting.

- An exact-match screen does not expand acronyms. Where both forms are common, use both somewhere on the page: the expansion in a bullet where the work is described, the acronym in Skills. "Digital signal processing (DSP)" the first time, then DSP.
- "C, C++" as two items, never "C/C++". A search for C++ may not match the slash form.
- Toolchain, bus, and standard names are the words the filter looks for: I2C, SPI, CAN, UART, FreeRTOS, KiCad, Altium, Verilog, SystemVerilog, IPC-2221, ISO 26262. If the user really used one, name it.
- Defense and export-controlled work can only be described by its technology class, not its program. Be specific about the transferable layer: the protocol, the method, the measured result.

Never add a keyword to raise a match score. A keyword the user cannot defend in an interview is a fabrication that gets caught in the later rounds.

## Reviewers

Tell the user to get several reviewers, not one. Post the page with the name, phone, address, and email removed to r/EngineeringResumes, hand it to the career center, and show it to two or three engineers. The reviewers will disagree. That is normal. Take each comment with a grain of salt and read the general reaction: if three strangers stumble on the same bullet, that bullet has a problem, whatever each one said the fix was. Give more weight to the reviewers who do the hiring in the field the user wants.

## What tailoring is not

- It is not a new resume per posting. Four or five versions cover most searches.
- It is not a keyword list. The bullets carry the words because the work used the tools.
- It is not padding. Thin experience stays thin on the page. The fix is a project or a lab, not a longer Skills line.
